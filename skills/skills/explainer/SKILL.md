# Explainer

**Format** 1920×1080, 30 fps. Length follows the content; cut anything that doesn't teach.

**Structure**
1. Promise (0–10 s): what the viewer will be able to do or understand. One sentence from the footage, plus a title.
2. Steps or sections in a logical order — reorder takes if it makes the explanation clearer.
3. Recap: the one-line summary, then end.

**Cutting**
- Transcribe everything. Cut mistakes, repeats, "um"s and pauses over ~0.5 s, but keep a natural speaking rhythm — slower than a short.
- Keep screen recordings on screen long enough to read; never cut mid-action.

**Graphics** (HyperFrames overlays)
- Chapter title at the start of each section: small, top-left, 2–3 s.
- Callouts: when a key term, number or command is said, show it as text for as long as it is discussed.
- Optional lower-third with the presenter's name once, only if the user gave it.
- One typeface and one accent colour throughout. Calm animation (fade/slide ≤ 0.4 s).

**Captions** Off by default; add full-sentence captions at the bottom if the user asks.

**Audio** Voice clear and even. Music optional, very low (0.05–0.1) and only under intro and transitions.

**Check before replying** A newcomer could follow it · every callout matches what is said · no dead air.
